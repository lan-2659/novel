# 2026-08-28-001 长篇多卷化改造（P0–P3）

## 时间与用户需求

- **时间**：2026-08-28
- **需求**：将系统从「一本书 = 全书大纲 + 全书规划 + 章节」升级为「一本书多卷」：
  - P0：新增卷（Volume）数据结构；双层状态机（全书阶段 + 卷内阶段）；分层上下文构建器。
  - P1：章节确认后自动更新追踪信息（人物状态/伏笔/摘要）；章节规划改为按卷生成（15~30 章，可滚动）。
  - P2：分卷浏览与写作 API + 前端；按卷导出 + 合并导出。
  - P3：数据库性能优化（章节索引 + 列表分页）。

## 实现内容

- **用户确认**：全部实施 P0–P3；全书级 `chapter_plans` 迁移进卷后废弃；现有数据允许重置。
- **实现方式**：
  - 数据模型：新增 `Volume` 表（project_id/number/title/outline/chapter_plan/summary/status/stage）；`Chapter` 增 `volume_id` 与复合索引 `(project_id, volume_id, number)`；`Project` 增 `current_volume_id / character_state_summary / foreshadowing_items / global_summary`；移除 `ChapterPlan`。
  - 状态机（`pipeline/stages.py`）：全书阶段 `idea→setting→outline→writing→completed` + 卷内阶段 `volume_outline→volume_plan→writing→volume_completed`；全书完成 = 所有卷完成；卷完成后自动把 `current_volume` 推进到下一卷。
  - 上下文构建器（`context_builder.py`）：四层上下文（全书级 / 分卷级 / 跨卷追踪 / 近期上下文），供章节与卷大纲/卷规划生成使用；生成下一卷规划时携带前置卷摘要与全局追踪，实现后卷呼应前卷。
  - 追踪（`services/tracking_service.py`）：章节确认后调用 LLM 提取人物状态变化/新伏笔/已回收伏笔/剧情摘要，合并写入 Project 与 Volume；尽力而为，失败不阻断确认。
  - 服务：`volume_service.py`（卷 CRUD、卷大纲/规划生成、卷内章节 SSE、卷完成推进、单卷/合并导出）；`generation_service.py` 收敛为全书设定/大纲，全书大纲生成后自动创建第一卷。
  - API：新增 `/api/projects/{id}/volumes`、`/api/volumes/{id}`、`/api/volumes/{id}/outline`、`/api/volumes/{id}/chapter-plan`、`/api/volumes/{id}/chapters`、`/api/volumes/{id}/export`；章节列表支持 `volume_id` 过滤与 `page/page_size` 分页；保留项目级章节生成入口（委托到当前卷）。

  - 数据库：按用户确认重置为多卷 schema（旧库备份为 `backend/data/novel.db.bak`）。

## 遇到的问题与解决方式

1. **`models/__init__.py` 残留 `ChapterPlan` 导入**：删除模型后未同步 `__init__`，导致 ImportError。解决：同步更新 `__init__.py` 导出。
2. **`context_builder.py` 相对导入越界**：该文件位于 `app/` 顶层却使用 `from ..models...`。解决：改为 `.models` / `.repositories` 单点相对导入。
3. **SQLAlchemy 双向外键歧义**：Project 与 Volume 之间存在两条 FK 路径（`Volume.project_id` 与 `Project.current_volume_id`），`Project.volumes` 无法自动判定连接条件。解决：为 `Project.volumes` / `Volume.project` 显式指定 `foreign_keys`，并为 `current_volume` 使用 `post_update=True`。
4. **残留 uvicorn 进程锁定数据库**：先前会话遗留两个 uvicorn 进程占用 `novel.db`，导致删除文件失败（错误被 `SilentlyContinue` 吞掉）且旧 schema 被保留。解决：定位并 `Stop-Process` 后重置数据库。
5. **终端不接受 `cd` 前缀**：持久终端的 cwd 固定在项目根，`cd backend` 被工具剥离。解决：改用 `python -m uvicorn --app-dir backend` 与绝对路径。

## 经验总结

- **长篇小说系统的核心是「分层上下文 + 滚动摘要」**：不要把所有内容塞进 prompt；全书级信息稳定、分卷级信息按需、追踪信息滚动压缩、近期上下文精确截取，才能既保证一致性又不过载。
- **双层状态机的关键是「卷完成推进 + 当前卷标识」**：`Project.current_volume_id` 指向正在写作的卷，卷完成后按 number 自动推进到下一卷，全部完成后全书 `completed`；创建卷时仅在当前卷为空/已完成时才接管当前卷，避免打断写作。
- **双向外键的关系需要显式 `foreign_keys`**：同一对表之间存在多条 FK 时，SQLAlchemy 必须显式指定，否则报「multiple foreign key paths」。
- **SSE 与追踪的失败隔离**：章节确认是用户主操作，追踪提取是后台增强——把追踪做成「尽力而为 + 事务回滚」，即使 LLM 提取失败也不影响确认主流程。
- **真实 LLM 端到端验证价值巨大**：假 LLM 只验证流程正确性，真实 LLM 验证了 prompt 质量、四层上下文的实际效果（生成内容与设定/卷大纲高度一致）以及追踪提取的可用性。
- **残留进程会静默破坏数据库操作**：Windows 下被进程锁定的文件删除失败时，若用 `SilentlyContinue` 会掩盖问题；应先排查 python/uvicorn 进程再操作数据文件。
