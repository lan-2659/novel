- **实现方式**：

  - 前端：Vue 3 全局构建静态应用（`frontend/vendor/vue.global.prod.js` 已下载），由 FastAPI `StaticFiles` 托管，原生 `fetch` 读取 SSE 流。
- **涉及文件**：`backend/app/**`（约 20 个模块）、`frontend/**`、`backend/tests/**`、`.env.example`、`README.md`。
- **关联 Task**：TASK-001 ~ TASK-012（见 `.tasks/tasks.json`）。
- **验证方式与结果**：
  - `pytest` 8 个用例全部通过（假 LLM，覆盖全流程）。
  - 启动验证通过：`/api/health` 返回 `{"status":"ok"}`；`/` 返回前端页面；`POST /api/projects` 创建项目成功。

## 遇到的问题与解决方式

1. **Node/npm/pnpm 未安装**：前端无法用 Vite 构建。解决：改用 Vue 3 全局构建产物（CDN 下载到本地 `vendor/`），由 FastAPI 托管静态文件，前端零构建、零 Node 依赖。
2. **OpenAI SDK 升级到 3.0.0**：不确定接口是否兼容，先通过 `inspect.signature` 确认 `chat.completions.create` 签名与 1.x 一致后再编写客户端，避免盲目照搬旧代码。
3. **启动验证产生脏数据**：验证时创建了测试项目，事后定位到 SQLite 实际落在项目根目录 `data/novel.db`（而非 `backend/data/`），已删除保持初始状态干净。

## 经验总结

- **无 Node 环境时，静态 Vue（UMD 全局构建）是 SPA 的最低成本方案**：下载单个 `vue.global.prod.js` 到本地即可，配合 DOM 内联模板（全局构建自带编译器），无需任何构建工具，FastAPI `StaticFiles(html=True)` 即可完整托管。
- **测试与真实 LLM 解耦**：把 LLM 抽象为 `LLMClient` 接口，通过 FastAPI `dependency_overrides` 注入假实现，使「生成类」接口也能被确定性测试覆盖，不依赖外部 API 与网络。
- **SSE 与错误码的配合**：章节生成前先做同步校验（`ensure_can_generate_chapter`）返回标准 4xx JSON，真正进入流式后错误通过 `data: {"type":"error",...}` 事件传递——两者分离，前端才能正确区分「前置不满足」与「生成中失败」。
- **阶段只进不退**：`advance_stage` 保证编辑旧内容不会让项目阶段回退，避免「继续写作」定位错乱。
